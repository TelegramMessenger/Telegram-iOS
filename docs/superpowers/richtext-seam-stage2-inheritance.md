## 1. Phase-6 gate item 23 — a STAGE-2 ENTRY CONDITION, reproduced verbatim

**Stage 1 cannot fail this item by construction; it is stage 2's to discharge.**

- [ ] **23. D38's tautological continuity guard is decided BEFORE stage 2 routes a mutation** (Task 41 review M5 — this item is not in the spec, and it exists because the obligation had no other owner).
  **Do not check this box by inspecting stage-1 code — stage 1 cannot fail it.** `synchronizeAfterExternalChange`'s guard is `change.oldRevision == documentRevision`, and `synchronizingExternalChange` sources `oldRevision` from the backend's own adopted baseline (deviation D38), so at those five call sites **the guard cannot fail by construction**. That was accepted for stage 1 on a measured argument: `prepareAndRun` has zero production callers, so the backend's counter never advances on its own, and a guard comparing a value to itself costs nothing while nothing else can move it.
  **The moment stage 2 routes a real mutation through `prepareAndRun`, that argument expires and the guard becomes a comparison that LOOKS live and cannot fire.** Two things must therefore be settled before stage 2's first mutation lands, and settled in stage 2's own plan, not here:
  1. **Where `oldRevision` comes from.** The literal fix — passing the document's baseline — was BUILT and MEASURED at Task 41: it makes all five sites report `revision continuity violated … has adopted 0` and does **not** repair anything. So the answer is not "just switch the source"; the backend's cache must first be made to track the document, which is precisely what owning the mutation path means.
  2. **Whether the guard should exist at all in its current form.** Task 41 removed its second consumer (`.preserveIfRebasable`'s stale-cache read) via `RichTextInputExternalChangeReason.preservesTextOffsets`. If no consumer remains that a live guard would protect, deleting it is a legitimate answer — but it must be a decision with that sentence written down, not an omission.
  **Pass condition:** stage 2's plan contains a named task that owns this, quoting Task 41's measurement, OR a recorded decision to delete the guard. Paste whichever into the gate record. **An unchecked box here means stage 2 starts with a safety check that is decorative** — which is the state Task 41 could not fix and deliberately did not paper over.
